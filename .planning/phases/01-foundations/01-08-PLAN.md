  <name>Task 2: Verify PG 18.3 compatibility end-to-end (CHECKPOINT if fails)</name>
  <files>
    - packages/db/dist/migrate.js (built)
  </files>
  <action>
**Step A — direct migration:**
```
pnpm --filter @simplevault/db build
docker run --rm \
  --network simplevault_backend \
  -e DATABASE_URL=postgres://simplevault:changeme_dev_only@postgres:5432/simplevault \
  -v "$PWD:/repo" -w /repo/packages/db \
  node:22-alpine sh -c "corepack enable && corepack prepare pnpm@9.15.0 --activate && pnpm install --frozen-lockfile && node ./dist/migrate.js"
```
Expected: exits 0 with "Migrations applied".

Inside Postgres, verify:
```
docker exec simplevault-postgres-1 psql -U simplevault -d simplevault -c "\dt"
```
Expected: lists `users` and `__drizzle_migrations`.

**Step B — idempotency:** Run the same migrate command again. Expected: exits 0, no new migrations applied (drizzle journal logic).

**Step C — through the api container's prestart hook:**
```
docker compose up -d --build api
docker compose logs api | grep -i 'migrations applied'
```
Expected: log line "Migrations applied" appears, then "Starting api...", then "Nest application successfully started".

**IF ANY STEP FAILS:** This is a CHECKPOINT. Surface to operator with:
1. Exact error message + stack
2. Hypothesis: PG 18.3 incompat? Drizzle Kit version? `pg` driver?
3. Options:
   - (a) Pin to drizzle-orm@<lower version> known good with PG 18
   - (b) Patch generated SQL manually (if syntax issue)
   - (c) Ask operator to downgrade Dokploy Postgres to 17.x
4. Wait for operator decision.

If everything passes: write `.planning/phases/01-foundations/01-08-COMPAT.md` certifying PG 18.3 compatibility with the exact dep versions. This document is what `infra-deployment-auditor` will reference in the gate.
