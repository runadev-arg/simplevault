**Custom command `cy.seedInvite(email)`**: shells out to `pnpm cli invite create --email <email>` via Cypress's `cy.exec` and captures the printed code from stdout.

**`auth-happy.cy.ts`**:
1. `cy.seedInvite("happy@test.local")` → captures CODE.
2. Visit /signup; type CODE; advance.
3. Type master password (≥12 chars, classes); advance.
4. Capture displayed secret-key; check confirmation; re-paste; advance.
5. Capture displayed mnemonic; check confirmation; on confirm step, read the in-DOM challenge indices, type the right words; advance.
6. Click submit; wait for /login redirect.
7. Type email + password + secretKey on /login; submit.
8. Assert redirect to /me; assert email is visible.
9. Click logout; assert redirect to /login.

**`auth-sad.cy.ts`**:
1. `cy.seedInvite("sad@test.local")` → walk through to a successful signup → logout.
2. Visit /login; submit with wrong secretKey → assert canonical error message.
3. Re-attempt signup with the already-redeemed invite → assert canonical INVITE_INVALID error.
4. Login successfully; visit /me; from DevTools/test capture the refresh cookie; force a /auth/refresh with the OLD cookie after one rotation → assert 401 + redirect to /login on the next page transition.

Tests should be hermetic: each spec uses a unique email and is idempotent against a wiped DB at the start (a `beforeEach` runs `pnpm db:reset` or truncates the auth tables).

  <action>
**SECURITY-NOTES.md** — append a section "Argon2id calibration (one-time, before production cutover)":
- Why: per-deployment calibration ensures Argon2id wall-time stays in the 500–1000ms band on the actual production hardware (per CRYPTO-STACK.md §2). Default fallback values are conservative and may run too slow on a small VPS.
- How:
  1. SSH to the Dokploy host.
  2. `docker exec -it <api-container> simplevault-cli argon2 calibrate`.
  3. Copy the printed `ARGON2_MEMORY_COST` + `ARGON2_TIME_COST` values into Dokploy's env-var UI for both `api` and `web` services.
  4. Redeploy both services.
- Caveat: calibration is per-hardware. If the operator migrates VPS, re-run.

**DOKPLOY-DEPLOY.md** — extend the env-var table (Phase 01 left placeholders) with the Phase 02 additions:

| Var | Required | Format | Notes |
|---|---|---|---|
| `JWT_SECRET` | yes | 32+ bytes random | `openssl rand -base64 48`. Never commit. |
| `SERVER_INVITE_SECRET` | yes | 32+ bytes random | Used to HMAC invite codes. |
| `SERVER_RECOVERY_HMAC_SECRET` | yes | 32+ bytes random | Used to outer-HMAC the inner sha256(phrase). |
| `SERVER_ARGON_SALT` | yes | 16 bytes random base64 | Server-wide salt for Argon2id(secret_key) verifier. |
| `SERVER_EVENT_SECRET` | yes | 32+ bytes random | Used to hash IPs in audit events. |
| `ARGON2_MEMORY_COST` | optional | integer (KiB) | Operator runs `argon2 calibrate` to set; default `65536` (64MiB). |
| `ARGON2_TIME_COST` | optional | integer | default `3`. |
| `ARGON2_PARALLELISM` | optional | integer | always `1` for libsodium WASM. |

Also document: invite codes for v1 are operator-issued via `pnpm cli invite create --email <addr>` and delivered **out-of-band** (Signal, in-person, or operator's own email client). No SMTP integration in v1; that's deferred to Phase 07. The `email` field is a binding identifier on the invite, not a delivery target.
