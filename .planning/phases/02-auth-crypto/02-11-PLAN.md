**`login-derivations.ts`**:
```ts
export async function buildLoginEnvelope({ email, password, secretKey, argon2Params, serverArgonSalt }) {
  await ready();
  const argon2SecretKeyHash = await deriveKey(secretKey, serverArgonSalt, argon2Params);
  return { email, argon2SecretKeyHash };
}
export async function unlockMasterDek({ password, secretKey, email, argon2Params, userArgonSalt, wrappedMasterDek }) {
  const masterKek = await deriveMasterKek({ password, secretKey, email, argon2Params, userArgonSalt });
  const aad = encodeAad(argon2Params, sha256(emailLowercasedBytes(email)));
  return await unwrapKey(wrappedMasterDek, masterKek, aad);
}
```
(Note: login flow needs `userArgonSalt` from the server — extend the /auth/login response to include it alongside the wrapped material. Plan 08's response contract already lists "wrapped_master_dek + ... + argon2Params + serverArgonSalt + wrapped private keys". Add `userArgonSalt` if not yet there.)

**`access-token-store.ts`**:
```ts
let _accessToken: string | null = null;
let _expiresAt: number = 0;
export const accessTokenStore = {
  set(jwt: string) { _accessToken = jwt; _expiresAt = decodeExp(jwt) * 1000; },
  get() { return _expiresAt > Date.now() ? _accessToken : null; },
  expiresAt() { return _expiresAt; },
  wipe() { _accessToken = null; _expiresAt = 0; },
};
```

**/login page.tsx** (`"use client"`): form with email + password + secretKey inputs. On submit:
1. Pre-flight: GET `/auth/login/preflight?email=…` — wait, that would leak. Instead: use a POST /auth/login/preflight that returns argon2Params + serverArgonSalt for the email, with the SAME timing as a full login (i.e. always run dummy Argon2id on miss). **Simpler alternative:** put argon2Params + serverArgonSalt in the /auth/login REQUEST flow as a two-round-trip ceremony. **Even simpler:** make `argon2Params` and `serverArgonSalt` GLOBAL (server-wide) instead of per-user — single Argon2id profile for all users. Re-discuss in SUMMARY; for v1 with ≤50 users, **global params are acceptable** and remove the preflight enumeration risk. **Adopt the global-params approach for Phase 02**; if/when per-user calibration is desired (Phase 11+), revisit.

3. On 200: `accessTokenStore.set(res.accessToken)`; unlock master_DEK via `unlockMasterDek(...)` and stash via `keyStore.set("masterDek", ...)`; redirect to `/me`.

**`auth-context.tsx`** — Client provider exposing `{ user, accessToken, logout, refresh }`. On mount: if no accessToken in store → call /auth/refresh once (transparent re-auth from cookie). If 401 → null user.

**`use-auto-refresh.ts`** — schedules a setTimeout for `(expiresAt - now) - 60_000`. On fire: calls /auth/refresh; on 200: updates store. On 401 AUTH_REFRESH_REUSED: calls `keyStore.wipe()` + `accessTokenStore.wipe()` + redirect to /login. Re-schedules after each successful refresh. Listens to `visibilitychange` to refresh early if the tab was backgrounded past expiry.

**(authed) route group**: `apps/web/src/app/(authed)/layout.tsx` is a client layout that uses `useAuth()`; if `accessToken === null` → redirect to /login.

**/me page**: fetches GET /me with `Authorization: Bearer <accessToken>`; renders the four fields. Has a "Logout" button → calls /auth/logout, wipes stores, redirects to /login.
