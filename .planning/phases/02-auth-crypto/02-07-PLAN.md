<objective>
Land the invite-redeem and signup endpoints. These are the entry points to creating a user account; everything Phase 02+ depends on this working correctly. The API is **strictly an envelope**: the client does all the crypto (master_KEK derivation, key generation, wrapping, recovery_hmac inner step) and posts the artifacts. The server stores them, never plaintext.

`POST /invite/redeem` is informational — it tells the client what `argon2_params` + `server_argon_salt` to use for derivation. Calling it does NOT mark the code redeemed; only successful `POST /auth/signup` does.

`POST /auth/signup` accepts the artifacts and persists them atomically with the invite-redemption.
</objective>

**`apps/api/src/crypto/crypto.service.ts`** — server-side facade:
- Reads env: `SERVER_INVITE_SECRET`, `SERVER_RECOVERY_HMAC_SECRET`, `JWT_SECRET`, `ARGON2_MEMORY_COST` / `ARGON2_TIME_COST` (default to `ARGON2_DEFAULT_PARAMS` if unset, log a WARN).
- Exposes:
  - `inviteCodeHmac(rawCode: Buffer): Buffer` — HMAC-SHA256 with `SERVER_INVITE_SECRET`.
  - `outerRecoveryHmac(innerSha256OfPhrase: Buffer): Buffer` — HMAC-SHA256 with `SERVER_RECOVERY_HMAC_SECRET`. (Inner sha256 is computed by the CLIENT via `@simplevault/crypto.computeRecoveryLookupHash`; client posts the inner hash; server applies the outer HMAC and stores result. Plaintext mnemonic NEVER touches the server.)
  - `argon2Params(): Argon2Params` — returns the env-or-default params.
  - `serverArgonSalt(): Buffer` — server-wide salt for the Argon2id(secret_key) verifier (one value per deployment, in env: `SERVER_ARGON_SALT`, base64).
  - `verifySecretKeyHash(secretKeyHashCandidate, stored)`: constant-time `Buffer.compare`-replacement with `crypto.timingSafeEqual`.
- Fails fast in `onModuleInit` if any required env is missing or wrong size (32B for secrets, 16B for SERVER_ARGON_SALT).

**`InviteController`** — `POST /invite/redeem`:
- DTO: `{ code: string }` (Zod `.strict()` schema with regex matching the base32-formatted code from Plan 06).
- Service:
  1. Compute `code_hash = cryptoSvc.inviteCodeHmac(decode(code))`.
  2. SELECT from `invite_codes` WHERE `code_hash = $1` LIMIT 1.
  3. If not found, OR `expires_at < now()`, OR `redeemed_at IS NOT NULL` → return 400 with `INVITE_INVALID` (uniform — DO NOT differentiate; defends enumeration of the email associated with a code).
  4. If valid → return 200 with `{ inviteId, email, argon2Params, serverArgonSalt: base64 }`.
- Apply rate-limit: 10/IP/hour on this endpoint (advisory; lookup is cheap).
- Log via Pino: `invite.redeem.ok` / `invite.redeem.fail` (no raw code in log; use `code_hash` hex prefix).

Extend `packages/shared/src/error-codes.ts` to add `INVITE_INVALID`, `INVITE_EXPIRED`, `INVITE_ALREADY_REDEEMED` (though the controller collapses all three into INVITE_INVALID externally — internal logging keeps the distinction).

**Signup DTO** (Zod `.strict()`, every field validated):
```ts
const SignupSchema = z.object({
  inviteId: z.string().uuid(),
  argon2SecretKeyHash: z.string().regex(/^[A-Za-z0-9+/=]+$/).transform(b64decode32B),
  argon2Params: z.object({ memoryKiB: z.number().int().positive(), iterations: z.number().int().positive(), parallelism: z.literal(1) }),
  userArgonSalt: z.string().transform(b64decode16B),
  wrappedMasterDek: z.string().transform(b64decode),       // ciphertext + nonce blob (canonical layout)
  wrappedMasterDekRecovery: z.string().transform(b64decode),
  recoveryInnerHash: z.string().transform(b64decode32B),    // sha256(phrase) — server applies outer HMAC and stores
  userPubKey: z.string().transform(b64decode32B),
  wrappedUserSigningSk: z.string().transform(b64decode),
  wrappedUserKxSk: z.string().transform(b64decode),
}).strict();
```
The `.strict()` is what guarantees the server rejects any payload that contains the disallowed fields (`password`, `secret_key`, `recovery_phrase`, etc.) — REQ-CRYPTO-003 / REQ-CRYPTO-006.

**SignupService.signup(input)**:
1. Open Drizzle transaction.
2. SELECT invite_codes WHERE id = input.inviteId FOR UPDATE.
3. If row not found, expired, redeemed, OR redeemed_user_id IS NOT NULL → throw HttpException 400 (uniform `INVITE_INVALID`).
4. Compute `recoveryHmac = cryptoSvc.outerRecoveryHmac(input.recoveryInnerHash)`.
5. INSERT users with all the input artifacts + `argon2_secret_key_hash` (input verifier — server has NOT verified anything yet; it just stores) + `recovery_hmac` + `server_argon_salt` (from env) + `argon2_params` (from input — verified ≥ floor in next step).
   - Pre-INSERT: validate `argon2Params` ≥ `ARGON2_FLOOR_PARAMS` (defends KDF param downgrade at signup); else 400 with `VALIDATION_FAILED`.
6. UPDATE invite_codes SET redeemed_at = now(), redeemed_user_id = NEW user.id WHERE id = inviteId.
7. Commit. Return `{ userId, email }`.
8. Catch unique-constraint violations on email → return 400 with **same `INVITE_INVALID` external code** to avoid enumeration. (Internal log keeps `SIGNUP_DUPLICATE_EMAIL`.)

Apply rate-limit: 3/IP/hour per REQ-RATELIMIT-003 (returns 429 with `Retry-After`).

Pino events emitted: `auth.signup.ok` (with userId + ip_hash + ua_family) / `auth.signup.fail` (with reason category, no PII).

NO email is sent (out-of-band invite delivery, REQ deferred to Phase 07).
