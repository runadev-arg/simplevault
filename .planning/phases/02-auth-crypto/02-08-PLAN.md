<objective>
Land the three remaining auth endpoints: login (with timing floor + rate-limit), refresh (with rotation + family-revoke-on-reuse), logout (with family revoke). Together with Plan 07, this gives the full Phase 02 auth surface.

Login is **stateless about the master_KEK**: the server receives `argon2_secret_key_hash` (the verifier value the client computed by running Argon2id against the user's input secret_key + the server-provided server_argon_salt + argon2_params); the server timing-safe-compares against `users.argon2_secret_key_hash`. The server NEVER computes Argon2id over the master password — that derivation is purely client-side and the server never sees the password or the secret_key.
</objective>

  <action>
**Login DTO** (Zod `.strict()`):
```ts
const LoginSchema = z.object({
  email: z.string().email().toLowerCase().trim(),
  argon2SecretKeyHash: z.string().transform(b64decode32B),
}).strict();
```
(The client computes Argon2id locally over `secret_key + server_argon_salt + argon2_params` to produce this verifier — same construction the user did at signup. Plan 11 web flow drives this.)

**`timing-floor.ts`** export `DUMMY_HASH` initialised at module load to a fixed 32-byte value (e.g. derived from `JWT_SECRET` via HKDF — a deterministic-but-secret value so an attacker probing for the dummy can't compare).

**`LoginService.login(email, candidateHash, ip, ua)`**:
1. `const user = await db.query.users.findFirst(eq(users.emailLower, email))` (using the lower(email) index from Plan 05).
2. `const verifierToCheck = user?.argon2SecretKeyHash ?? DUMMY_HASH`.
3. `const ok = sodium.memcmp(candidateHash, verifierToCheck)`. (Constant-time. `memcmp` runs regardless of `user` truthiness.)
4. If `!user || !ok` → emit Pino `auth.login.fail` with reason category, return 401 `AUTH_INVALID_CREDENTIALS` — uniform body shape.
5. If success: create session via `SessionService.createOnLogin(userId, ip, ua)`:
   - Generate `rawRefreshToken = randomBytes(32)`; `refreshTokenHash = blake2b256(rawRefreshToken)`.
   - INSERT user_sessions: family_id = newUuid, refresh_token_hash, expires_at = now() + 30d, ip_hash, ua_family.
   - Return `{ rawRefreshToken, sessionId, familyId }`.
6. Issue access JWT via `JwtService.sign({ sub: userId, sid: sessionId, fam: familyId }, { expiresIn: 900, kid: "primary" })` using HS256 + JWT_SECRET.
7. Return body containing: accessToken, the user's wrapped_master_dek + wrapped_master_dek_recovery + argon2Params + serverArgonSalt + wrapped private keys (the client needs these to decrypt locally).
8. Set Set-Cookie: `__Host-refresh=<rawRefreshTokenBase64>; HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=2592000`.
9. Emit Pino `auth.login.ok` (userId, ip_hash, ua_family).

**JwtService**:
- Constructor: read JWT_SECRET (≥32B); fail fast if missing.
- `sign(claims, opts)`: jose `SignJWT` with HS256, `kid: "primary"`.
- `verify(token)`: jose `jwtVerify`; throws on bad signature / expired.

**Rate-limit**: install `@nestjs/throttler@^6` with Redis storage (ioredis already injected); apply two throttlers on the login route: `{ ttl: 900_000, limit: 5 }` keyed by IP, AND `{ ttl: 900_000, limit: 10 }` keyed by lowercased email (custom tracker reading the body).

  <files>

  <action>
**Refresh endpoint**: reads `__Host-refresh` cookie; no body.

**`SessionService.rotate(rawToken, ip, ua)`** in a single transaction:
1. `tokenHash = blake2b256(rawToken)`.
2. SELECT user_sessions WHERE refresh_token_hash = $1 FOR UPDATE.
3. If not found → 401 `AUTH_INVALID_CREDENTIALS`.
4. If `expires_at < now()` OR `revoked_at IS NOT NULL` → 401 `AUTH_INVALID_CREDENTIALS`.
5. **If `used_at IS NOT NULL`** → REUSE DETECTED:
   - `UPDATE user_sessions SET revoked_at = now() WHERE family_id = $f AND revoked_at IS NULL`.
   - Emit Pino `auth.refresh.reuse_detected` (familyId, userId, ip_hash, ua_family).
   - Return 401 `AUTH_REFRESH_REUSED` (a specific code; client should force re-login).
6. Else:
   - Generate new raw token + hash.
   - INSERT new session row (family_id = old.family_id, prev_token_id = old.id, refresh_token_hash = newHash, expires_at = now() + 30d, ip_hash, ua_family).
   - UPDATE old row SET used_at = now(), revoked_at = now().
   - Commit.
7. Mint a new access JWT for old.userId.
8. Return new body + new Set-Cookie with the new raw token.

Apply rate-limit: 30/IP/15min on /auth/refresh (loose — legitimate clients refresh ~every 15min).

`refresh.controller.ts` wires this; emits Pino events `auth.refresh.ok`, `auth.refresh.fail`, `auth.refresh.reuse_detected`.
  </action>
  <verify>
- E2E: login → first refresh succeeds, cookie rotated. Re-presenting the OLD cookie returns 401 AUTH_REFRESH_REUSED; querying user_sessions shows ALL rows in that family have revoked_at set.
- Concurrent-refresh test: two simultaneous refreshes with the same token — one wins (rotates), the other hits the SELECT FOR UPDATE serialisation and either sees `used_at IS NOT NULL` (reuse path) or also rotates (race tolerance). Document the chosen behaviour in SUMMARY.
  </verify>

Refresh rotation atomic; family-revoke-on-reuse working.
