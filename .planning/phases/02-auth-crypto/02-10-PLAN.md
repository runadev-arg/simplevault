<objective>
Build the `/signup` multi-step flow. The flow's job is to (a) generate the user's three secrets client-side (master password input + secret_key generation + recovery phrase generation), (b) force the user to acknowledge they've recorded both the secret_key and the recovery phrase, (c) derive the key hierarchy and wrap all the artifacts, and (d) post the artifacts envelope to `POST /auth/signup`.

The server NEVER sees the password, the secret_key, or the recovery phrase. The web bundle that runs this flow must NOT include `node:crypto`.
</objective>

**`signup-derivations.ts`** orchestrates `@simplevault/crypto`:
```ts
async function buildSignupEnvelope({ email, password, secretKey, mnemonic, argon2Params, serverArgonSalt }) {
  await ready();
  // 1. user_argon_salt: random 16B
  const userArgonSalt = sodium.randombytes_buf(16);
  // 2. master_KEK = deriveMasterKek({password, secretKey, email, argon2Params, userArgonSalt})
  const masterKek = await deriveMasterKek({ password, secretKey, email, argon2Params, userArgonSalt });
  // 3. master_DEK = sodium.randombytes_buf(32)
  const masterDek = sodium.randombytes_buf(32);
  // 4. user_KEK = sodium.randombytes_buf(32) (Phase 04 will use; we wrap and store now)
  // 5. Ed25519 + X25519 keypairs
  const sign = sodium.crypto_sign_keypair();
  const kx = generateKxKeyPair();
  // 6. wrappings — all with AAD encoding from key-hierarchy.encodeAad
  const wrappedMasterDek = await wrapKey(masterDek, masterKek, encodeAad(argon2Params, /* userId unknown — use email */ emailBytes));
  const recoveryKek = await deriveRecoveryKek({ mnemonic, userId: emailBytes /* placeholder; server fills userId post-INSERT — but the AAD must match later. Use a stable per-user binder, e.g. SHA256(email_lowercased)*/ });
  const wrappedMasterDekRecovery = await wrapKey(masterDek, recoveryKek, encodeAad(argon2Params, emailBytes));
  const wrappedUserSigningSk = await wrapKey(sign.privateKey, masterDek, encodeAad(argon2Params, emailBytes));
  const wrappedUserKxSk = await wrapKey(kx.secretKey, masterDek, encodeAad(argon2Params, emailBytes));
  // 7. argon2_secret_key_hash = Argon2id(secretKey, server_argon_salt, params)
  const argon2SecretKeyHash = await deriveKey(secretKey, serverArgonSalt, argon2Params);
  // 8. recoveryInnerHash = computeRecoveryLookupHash(mnemonic)
  const recoveryInnerHash = computeRecoveryLookupHash(mnemonic);
  return {
    inviteId, argon2SecretKeyHash, argon2Params, userArgonSalt,
    wrappedMasterDek, wrappedMasterDekRecovery,
    recoveryInnerHash,
    userPubKey: kx.publicKey,
    wrappedUserSigningSk, wrappedUserKxSk,
  };
}
```
(Note: AAD-binding-to-userId is impossible at signup-time because the server assigns the userId. Resolve by binding to SHA256(email_lowercased) — stable for the user's lifetime as long as email is the canonical identifier. Document this design decision in SUMMARY; `crypto-auditor` will scrutinise.)

**SubmittingStep**:
1. Show a "Deriving keys…" spinner; the Argon2id call blocks main thread for ~750ms.

3. On 200 → call `keyStore.wipe()` (zero out password / secretKey / mnemonic / masterKek / masterDek / private keys); redirect to `/login?signed_up=1`.
4. On 4xx → show canonical error message; allow retry (returning to step 1 IF inviteId was already used → user must request new invite).
