Mirror `apps/api/src/credentials/` structurally. The two load-bearing pieces (CAS PATCH + atomic history rotation) get TDD coverage; the rest is straight controller/service code.

## Tasks

<task type="tdd" id="T1">
  <action>
Write RED Vitest specs in `apps/api/src/pages/pages.service.spec.ts` covering:
1. PATCH succeeds when `version` matches current → row updated, version incremented, response `{id, version: current+1, updatedAt}`.
2. PATCH with stale `version` → throws `PAGE_VERSION_CONFLICT` (409); DB unchanged.
3. PATCH inserts the PRE-update snapshot into `page_versions` with the OLD ciphertext/nonce/aad/version.
4. PATCH after the page already has 10 history entries → after the new insert, oldest is deleted; `page_versions` count for that page stays at 10; the surviving 10 are versions `current-9 .. current` (descending).
5. PATCH transaction is atomic: simulate a failure inside the rotation step (e.g. mock the DELETE) → assert the UPDATE on `pages` is rolled back (version did NOT increment) AND no orphan `page_versions` row remains.
6. Cross-user PATCH (`vaultId` belongs to a different user) → 404 `PAGE_NOT_FOUND` (NOT 403; anti-enum).
7. Concurrent PATCH simulation: two clients send PATCH with the same current `version`; first wins, second gets 409.

Use the existing test-DB harness pattern from `credentials.service.spec.ts`. These should all FAIL initially (no impl yet).
  </action>
</task>

<task type="auto" id="T2">
  <action>
Implement `apps/api/src/pages/pages.service.ts` and `pages.controller.ts` to make T1 GREEN. Mirror `credentials.service.ts` for ownership joins (`SELECT ... FROM pages JOIN vaults ON pages.vault_id = vaults.id WHERE vaults.owner_user_id = $user`). The PATCH method is the only nontrivial piece — sketch:

```
db.transaction(async (tx) => {
  const current = await tx.select().from(pages).where(...ownership... AND id=$id).for("update");
  if (!current || current.version !== $witness) throw PAGE_VERSION_CONFLICT;
  await tx.insert(pageVersions).values({pageId: $id, version: current.version, ciphertext: current.ciphertext, nonce: current.nonce, aadParamsJson: current.aadParamsJson});
  const [updated] = await tx.update(pages).set({...new..., version: current.version+1, updatedAt: now()}).where(...id...).returning();
  // rotation: keep top 10 by version desc
  await tx.execute(sql`DELETE FROM page_versions WHERE page_id = ${$id} AND version NOT IN (SELECT version FROM page_versions WHERE page_id = ${$id} ORDER BY version DESC LIMIT 10)`);
  return updated;
});
```

Implement `GET /pages?q=<hex>`: when `q` is present, validate as 1-16 hex chars (= 0.5-8 bytes prefix), convert to bytea, filter `WHERE title_search_token >= $prefix AND title_search_token < $prefix_upper` (bytea range scan — index-friendly). When `q` absent → return all pages for the user's personal vault (metadata only; no ciphertext on the list endpoint to keep payloads light — clients GET `/pages/:id` for full envelope).

Implement `GET /pages/:id/history`: `SELECT version, ciphertext, nonce, aad_params_json, created_at FROM page_versions WHERE page_id=$id AND EXISTS (SELECT 1 FROM pages JOIN vaults ON ... WHERE pages.id=$id AND vaults.owner_user_id=$user) ORDER BY version DESC LIMIT 10`.

Wire the body-size middleware per-route (256 KiB default, 1 MiB ceiling). Wire the throttler ceiling. Register the module in `app.module.ts`.

</task>
