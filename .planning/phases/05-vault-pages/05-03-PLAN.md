## Tasks

<task type="tdd" id="T1">
  <action>
Write RED specs in `packages/crypto/test/vault-page-aad.test.ts`:

1. `buildVaultPageAad({vaultId: "00000000-0000-0000-0000-000000000001", pageId: "00000000-0000-0000-0000-000000000002", version: 1, email: "Alice@Example.com"})` returns the byte-pinned hex equal to `utf8("sv:vault-page:v1|") || sha256("alice@example.com") || utf8('{"pageId":"00000000-0000-0000-0000-000000000002","vaultId":"00000000-0000-0000-0000-000000000001","version":1}')`. Compute the expected hex with the same node one-liner pattern from 04-04 SUMMARY; pin it in the test.
2. Canonical JSON keys ordered alphabetically: `pageId` < `vaultId` < `version` (alphabet-true; reversed input → same output).
3. AAD changes when ANY of (vaultId, pageId, version, email) changes — 4 distinct AADs.
4. `await import("@simplevault/crypto/node")` does NOT export `buildVaultPageAad` (browser-only assertion).

Write RED specs in `packages/crypto/test/title-search.test.ts`:
1. `deriveTitleSearchKey(masterDek)` returns 32 bytes; deterministic for same `masterDek`; differs if `masterDek` differs by 1 bit.
2. `computeTitleSearchToken(key, "Meeting Notes")` returns 8 bytes; case-insensitive (same token for `"meeting notes"`, `"MEETING NOTES"`); whitespace-sensitive (different for `" meeting notes"`).
3. Pin a byte-equal regression vector: for `masterDek = Uint8Array(32).fill(1)`, `title = "test"`, the resulting token's hex is recorded in the test (compute once via the impl, paste hex, lock).
