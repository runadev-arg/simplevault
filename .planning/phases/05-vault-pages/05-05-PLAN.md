# Plan 05-05 — Web UI + Cypress smoke

UI surface + the closing E2E. No new crypto/API; just composition of 04-01..04-04 outputs.

## Tasks

<task type="auto" id="T1">
  <action>
Build `apps/web/src/lib/api/pages-client.ts` mirroring `credentials-client.ts`. Functions: `listPages(qPrefixHex?)`, `createPage(input)`, `getPage(id)`, `patchPage(id, input)`, `deletePage(id)`, `getPageHistory(id)`. Map server error code `PAGE_VERSION_CONFLICT` to a typed `PageVersionConflictError` so the editor can surface it. Map `PAGE_NOT_FOUND` to `PageNotFoundError`. Same fetch/auth pattern as the credentials client.
  </action>
</task>

<task type="auto" id="T2">
  <action>
Build the three pages under `apps/web/src/app/(authed)/`:

**`pages/page.tsx`** (list):
- On mount: derive `titleSearchKey` from in-memory `master_DEK` (via `keyStore`); fetch `listPages()`; for each page metadata, GET full envelope and decrypt to extract title + favorite flag (lazy: maybe only decrypt visible / first 50; for ≤50-user scale, eager-all is fine in v1).
- Search bar: debounced (200ms); on input, compute `computeTitleSearchToken(titleSearchKey, query.toLowerCase()).slice(0, prefixBytes)`, hex-encode, refetch `listPages(hex)`. Empty query → no `?q=`.
- Body-search toggle: client-side filter over decrypted titles + body text (REQ-VAULT-010); does NOT hit the server.
- Favorites pinned at top; rest sorted by `updatedAt` desc.
- Empty state CTA → `/page/new`.
- Use Aceternity card components vendored in Phase 04 (`apps/web/src/components/aceternity/`).

**`page/new/page.tsx`**:
- Mounts `<TipTapEditor>` with empty doc.
- Title input above the editor (separate field; populated into the doc as the first H1 OR carried in a `meta.title` field — match whatever `extractTitle` in 05-03 expects).
- Save button → `encryptPage({tiptapJson, isFavorite: false, meta}, masterDek, {vaultId, pageId: <fresh uuid>, version: 1, email})` → `createPage(envelope)` → redirect to `/page/[id]`.

**`page/[id]/page.tsx`**:
- Fetch + decrypt page; mount `<TipTapEditor value={tiptapJson} onChange={...}>`.
- Save button → re-encrypt with `version: currentVersion + 1`, send PATCH with witness `version: currentVersion`. On 409, show "This page changed in another tab — reload to see latest" modal.
- Side panel (collapsible): GET `/pages/:id/history`, decrypt each, render via `<RenderedTipTapHtml>` in a read-only preview pane. Click a version → preview only; explicit "Restore" button writes the historical content as a new PATCH (bumps version, history rotates).
- Delete button → confirm dialog → `deletePage(id)` → redirect to `/pages`.
- Favorite toggle re-encrypts with `meta.isFavorite` flipped.
  </action>
</task>

<task type="auto" id="T3">
  <action>
Write `cypress/e2e/pages-crud.cy.ts` covering:
1. Login → navigate `/pages` → empty state → click CTA → `/page/new`.
2. Type title "Meeting Notes" + body content → save → redirected to `/page/[id]`; `/pages` list now shows the page.
3. Search bar: type "Meet" → list filters to show only the page (server-side title-prefix search hits).
4. Body-search toggle: enable; search for body keyword; matches the page (client-side decrypt-and-filter).
5. Edit page → save → version increments (visible in history side panel as v2).
6. Loop: edit + save 10 more times → history panel still shows exactly 10 entries; oldest version is gone (rotation works).
7. Concurrent edit simulation (open second tab via `cy.visit` in a separate context, edit, save in tab1, then save in tab2) → tab2 surfaces "page changed in another tab" 409 modal.
8. XSS-attempt paste: paste `<script>alert(1)</script>` into editor → save → reload → no script element in DOM, no alert fired.
9. Link with `javascript:alert(1)` href → mark not applied; saved doc has no such link.
10. Delete page → redirect `/pages`; list empty again.

Run `pnpm cypress run --spec cypress/e2e/pages-crud.cy.ts`. Fix any flake. Document any new env vars (`PAGE_BODY_MAX_BYTES`) in `docs/operator/RUNBOOK.md` (one-line addition).
  </action>
</task>
