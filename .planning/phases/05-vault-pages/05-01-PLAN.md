# Plan 05-01 — Schema + constants foundation

Sequential foundation for Wave 2. Lands the structural skeleton everyone else imports.

## Tasks

<task type="auto" id="T1">
  <action>
Create `packages/db/src/schema/pages.ts` mirroring `packages/db/src/schema/credentials.ts` structure. Columns: `id` uuid PK defaultRandom, `vaultId` uuid NOT NULL FK → `vaults.id` cascade, `version` int NOT NULL default 1, `ciphertext` bytea NOT NULL, `nonce` bytea NOT NULL, `aadParamsJson` text NOT NULL, `titleSearchToken` bytea NOT NULL (8 bytes — enforce length in Zod, not at column type), `isLocked` boolean NOT NULL default false, `createdAt` / `updatedAt` timestamptz NOT NULL defaultNow. Indexes: `pages_vault_idx` on `vaultId`, `pages_title_token_idx` on `titleSearchToken`. JSDoc explains the AAD scheme references `AAD_LABEL_VAULT_PAGE` and that `is_locked` is a Phase-06 forward-compat hook (Phase 05 only writes false).

Create `packages/db/src/schema/page_versions.ts`. Columns: `id` uuid PK defaultRandom, `pageId` uuid NOT NULL FK → `pages.id` cascade, `version` int NOT NULL, `ciphertext` bytea NOT NULL, `nonce` bytea NOT NULL, `aadParamsJson` text NOT NULL, `createdAt` timestamptz NOT NULL defaultNow. Index: `page_versions_page_version_idx` on `(pageId, version desc)`. JSDoc: "last 10 ciphertext snapshots; rotation enforced in pages.service PATCH transaction."

Update `packages/db/src/schema/index.ts` barrel to re-export both.

Generate Drizzle migration: `pnpm --filter @simplevault/db generate` → produces `drizzle/0004_*.sql`. Verify the SQL has both `CREATE TABLE`s + indexes + FK constraints. No data backfill needed (no existing rows reference these tables).
  </action>
</task>

<task type="auto" id="T2">
  <action>

Add to `apps/web/src/lib/crypto/aad-labels.test.ts` an assertion that the new constant equals the exact byte string `"sv:vault-page:v1|"` (parity with how the credential label is tested).

Stub the helpers in `packages/crypto/src/browser.ts` (signatures + TODO bodies that throw `NotImplementedError`):
- `buildVaultPageAad({vaultId, pageId, version, email}, label = AAD_LABEL_VAULT_PAGE): Uint8Array`
- `canonicalPageAadJson({vaultId, pageId, version}): string`
- `deriveTitleSearchKey(masterDek: Uint8Array): Promise<Uint8Array>` — HKDF-Expand info `"sv:title-search:v1"`, length 32
- `computeTitleSearchToken(key: Uint8Array, title: string): Promise<Uint8Array>` — HMAC-SHA256, slice(0,8)

The constant `TITLE_SEARCH_HKDF_INFO = "sv:title-search:v1"` lives next to `AAD_LABEL_VAULT_PAGE` in `aad-labels.ts` (same FROZEN-constant module). Plan 05-03 will TDD the actual impls + parity tests.
  </action>
</task>

<task type="auto" id="T3">
  <action>

- `PageCreateSchema.strict()`: `vaultId` uuid, `ciphertext` Uint8Array, `nonce` Uint8Array length 24, `aadParamsJson` string ≤2048, `titleSearchToken` Uint8Array length 8, `version` literal 1.
