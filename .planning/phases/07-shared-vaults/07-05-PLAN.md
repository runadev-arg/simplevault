# Plan 07-05 — Web: invite flow + member management

**Wave 3** (after 07-02, 07-03)

## Goal
Vault owner can invite another user. Invitee sees pending invites, accepts
(which loads their vault DEK into keyStore), and can immediately use the vault.
Owner can view and remove members.

## T1 — `/vaults/:id/invite` (`apps/web/src/app/(authed)/vaults/[id]/invite/page.tsx`)

Flow:
1. Email input
2. On submit:
   a. `const kxPk = keyStore.getBytes("vault_dek:"+vaultId)` — owner must have DEK loaded
   b. Actually: owner needs their own vault DEK first. Load it from keyStore.
   c. `const {id: inviteeId, kxPublicKey} = await lookupUser(accessToken, email)`
   d. `const wrapped = await wrapVaultKey(vaultDek, kxPublicKey)`
   e. `await createInvite(accessToken, vaultId, inviteeId, wrapped)`
   f. Show success toast + clear input
3. Error handling: `E2016 VAULT_USER_NOT_FOUND` → "No account found for that email",
   `E2014 VAULT_ALREADY_MEMBER` → "User is already a member or has a pending invite"

**Precondition**: if `keyStore.getBytes("vault_dek:"+vaultId)` is undefined, show
error "Vault DEK not loaded — go back to the vault and try again."

## T2 — `/invites` (`apps/web/src/app/(authed)/invites/page.tsx`)

Bootstrap:
1. `getPendingInvites(accessToken)` → list of pending invites with `wrappedVaultKey`

Per invite card:
- Shows vault name + "invited by" email
- **Accept** button:
  a. `const kxPk = keyStore.getBytes("kx_pk")`
  b. `const kxSk = keyStore.getBytes("kx_sk")`
  c. `const vaultDek = await unwrapVaultKey(invite.wrappedVaultKey, kxPk, kxSk)`
  d. `keyStore.set("vault_dek:"+invite.vaultId, vaultDek)` — DEK now in memory
  e. `await acceptInvite(accessToken, invite.id)`
  f. `router.push("/vaults/"+invite.vaultId)`
- **Decline** button: `await declineInvite(accessToken, invite.id)` → remove from list

Error: if kx_sk missing → "Please sign in again to accept invites."

Empty state: "No pending invites."

## T3 — `/vaults/:id/members` (`apps/web/src/app/(authed)/vaults/[id]/members/page.tsx`)

Bootstrap:
1. `listMembers(accessToken, vaultId)` → member list

Render table: email | role | joined date | action button
- Owner sees "Remove" button for all non-owner members
- All members see "Leave vault" for their own row
- Confirm dialog before remove/leave

On confirm:
- `await removeMember(accessToken, vaultId, targetUserId)`
- If removing self (leave): `router.replace("/vaults")` + `keyStore.delete("vault_dek:"+vaultId)`
- If removing other: refresh member list

**Note**: `keyStore` doesn't currently have a `delete` method — add it:
`keyStore.delete(key: string): void` — zeros the bytes then removes from map.

## T4 — Navigation wiring

Add links:
- `/vaults/:id` page: "Invite" button → `/vaults/${id}/invite` (owner only, show based on role)
- `/vaults/:id` page: "Members" button → `/vaults/${id}/members`
- Top nav or `/vaults` page: "Invites" link → `/invites` (show badge if pending count > 0)

The pending invite badge requires a call to `getPendingInvites` in the layout or
a separate polling hook. **Simplest MVP**: just add an "Invites" link in the nav
bar (no badge), user checks manually. Badge is post-MVP.

## Acceptance

- Owner can invite by email; invitee sees invite on `/invites`
- Accept stores DEK in keyStore and redirects to vault
- Decline removes invite
- Owner can remove a member; member can leave vault
- `pnpm --filter @simplevault/web typecheck` — clean
