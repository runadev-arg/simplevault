# Plan 07-06 — Web: DEK plumbing for credential + page routes

**Wave 3** (after 07-02, 07-03)

## Goal
Existing credential create/edit routes and page create/edit routes work for
shared vaults by reading the vault DEK from keyStore when a `vaultId` query
param is present, falling back to `master_dek` for the personal vault.

## Background
Phase 04 credential routes hardcode `keyStore.getBytes("master_dek")` and
`listVaultPersonal(accessToken)` to resolve vaultId. For shared vaults, we
need:
1. vaultId from the URL (passed as `?vaultId=<uuid>`)
2. DEK from `keyStore.getBytes("vault_dek:${vaultId}")` if present, else `master_dek`
3. The AAD still binds `{vaultId, credentialId, version, email}` — no change to
   the crypto layer (it already uses the caller-supplied vaultId).

## T1 — Shared `useVaultDek` hook

**File:** `apps/web/src/lib/vault/use-vault-dek.ts`

```ts
import { keyStore } from "../auth/key-store";

/**
 * Resolves the encryption DEK for a given vault context.
 * Returns `master_dek` for the personal vault (vaultId === undefined or
 * vaultId === personalVaultId); returns `vault_dek:${vaultId}` for shared
 * vaults. Returns `undefined` if the DEK is not in keyStore (vault locked or
 * invite not yet accepted).
 */
export function resolveVaultDek(vaultId?: string): Uint8Array | undefined {
  if (vaultId === undefined) return keyStore.getBytes("master_dek");
  const sharedDek = keyStore.getBytes(`vault_dek:${vaultId}`);
  if (sharedDek !== undefined) return sharedDek;
  return keyStore.getBytes("master_dek"); // personal vault fallback
}
```

## T2 — Update `apps/web/src/app/(authed)/credential/new/page.tsx`

Accept `vaultId` from `useSearchParams()`:

```ts
const searchParams = useSearchParams();
const vaultIdParam = searchParams.get("vaultId") ?? undefined;
```

In the bootstrap effect:
- If `vaultIdParam` is set: skip `listVaultPersonal` → use `vaultIdParam` directly as `ctx.vaultId`
- If not set: use `listVaultPersonal` as before

In `onSave`:
- Replace `keyStore.getBytes("master_dek")` with `resolveVaultDek(ctx.vaultId)`
- Error if undefined: "Vault DEK not available — return to vault and try again."

Cancel → navigate to `/vaults/${ctx.vaultId}` if shared, else `/vault`.

## T3 — Update `apps/web/src/app/(authed)/credential/[id]/page.tsx`

Accept `vaultId` from `useSearchParams()` in the same way as T2.

In the bootstrap effect:
- If `vaultIdParam` is set: use it directly; skip `listVaultPersonal`
- DEK: `resolveVaultDek(vaultIdParam)`

Cancel/after-save → navigate to `/vaults/${vaultId}` if shared, else `/vault`.

## T4 — Update `CredentialCard` component

`CredentialCard` currently calls `keyStore.getBytes("master_dek")` internally
via `decryptCredential`. Check `apps/web/src/components/credentials/credential-card.tsx`.

If the card has the DEK hardcoded, add a `dek?: Uint8Array` prop; if undefined,
fall back to `keyStore.getBytes("master_dek")`. Pass `dek={vaultDek}` from the
shared vault list page (07-04 T4).

## T5 — Page routes (optional, same pattern)

Apply the same `useSearchParams()` + `resolveVaultDek` pattern to
`apps/web/src/app/(authed)/page/new/page.tsx` and
`apps/web/src/app/(authed)/page/[id]/page.tsx`.

For pages, the DEK is used in `encryptPage`/`decryptPage` as the `masterDek`
parameter. The shared vault would use its vault DEK for pages too.

**Scope**: implement if time permits; the minimum viable MVP only requires shared
vault CREDENTIALS (T2 + T3 + T4). Pages in shared vaults is a bonus.

## T6 — Wire "New" button in shared vault credential list

In `/vaults/:id` (Plan 07-04 T4), the "New" button should link to:
```
/credential/new?vaultId=${vaultId}
```

In the vault credential list's "Edit credential" flow, the `CredentialCard`
click navigates to `/credential/${credentialId}?vaultId=${vaultId}`.

- `/credential/new?vaultId=<shared-vault-id>` creates a credential encrypted
  under the shared vault DEK
- `/credential/<id>?vaultId=<shared-vault-id>` edits it
- Personal vault routes (`/credential/new` no param, `/credential/<id>` no param)
  still use `master_dek` — no regression
