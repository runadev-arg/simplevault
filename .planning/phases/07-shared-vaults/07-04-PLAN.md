# Plan 07-04 — Web: vaults list + create + shared vault credential view

**Wave 3** (after 07-02, 07-03)

## Goal
Users see all their vaults on `/vaults`, can create a shared vault at
`/vaults/new`, and browse credentials inside a shared vault at `/vaults/:id`.

## T1 — `apps/web/src/lib/api/vault-sharing-client.ts`

Typed wrappers for the vault-sharing API surface. Use the shared `request`
helper from `auth-client.ts`.

```ts
// Response types
export interface VaultListItem { id: string; name: string | null; kind: "personal" | "shared"; role: "owner" | "member"; memberCount: number; }
export interface UserLookupResult { id: string; kxPublicKey: Uint8Array; } // decoded from base64url
export interface PendingInvite { id: string; vaultId: string; vaultName: string; invitedBy: string; wrappedVaultKey: Uint8Array; createdAt: string; }
export interface MemberSummary { userId: string; email: string; role: string; joinedAt: string; }

// Functions
export function listAllVaults(accessToken): Promise<VaultListItem[]>
export function createGroupVault(accessToken, name, wrappedVaultKey: Uint8Array): Promise<{id: string; name: string}>
export function lookupUser(accessToken, email): Promise<UserLookupResult>
export function createInvite(accessToken, vaultId, inviteeId, wrappedVaultKey: Uint8Array): Promise<void>
export function getPendingInvites(accessToken): Promise<PendingInvite[]>
export function acceptInvite(accessToken, inviteId): Promise<void>
export function declineInvite(accessToken, inviteId): Promise<void>
export function listMembers(accessToken, vaultId): Promise<MemberSummary[]>
export function removeMember(accessToken, vaultId, userId): Promise<void>
```

## T2 — `/vaults` list page (`apps/web/src/app/(authed)/vaults/page.tsx`)

Bootstrap:
1. `listAllVaults(accessToken)` — get all vaults
2. Render two sections: "Personal vault" (card linking to `/vault`) + "Shared vaults" (card grid, each linking to `/vaults/${id}`)
3. Empty-state for shared vaults: CTA → `/vaults/new`
4. "New vault" button → `/vaults/new`

No decryption on this page — vault names are plaintext (they're public enough
within the vault's member set; the name is not a secret).

## T3 — `/vaults/new` create page (`apps/web/src/app/(authed)/vaults/new/page.tsx`)

Flow:
1. Name input (required, 1–100 chars)
2. On submit:
   a. `await ready()`
   b. `const dek = await generateVaultDek()`
   c. `const myKxPk = keyStore.getBytes("kx_pk")` (stored at login; see Phase 02)
   d. `const wrapped = await wrapVaultKey(dek, myKxPk)`
   e. `const {id} = await createGroupVault(accessToken, name, wrapped)`
   f. `keyStore.set("vault_dek:"+id, dek)` — so credentials can be encrypted immediately
   g. `router.replace("/vaults/" + id)`

Error state: if kx_pk is missing in keyStore ("vault locked"), surface an error
and direct user to re-sign-in.

## T4 — `/vaults/:id` shared vault credential list (`apps/web/src/app/(authed)/vaults/[id]/page.tsx`)

Reuse the same structure as `/vault` (personal vault list, Plan 04-09):
1. `listVaultPersonal` → NO; instead call `GET /vault/personal` only for personal,
   or for shared use `GET /vaults/:id/credentials` — but wait, Phase 04 already
   built `GET /vault/personal` which returns `{vaultId, credentialIds[]}`. For
   shared vaults, the same `GET /vault/personal` won't work.

   **Solution**: add a new client call `listVaultCredentials(accessToken, vaultId)`
   that hits `GET /credentials?vaultId=:id` — OR reuse the existing
   `listVaultPersonal` response shape from the existing vault controller but for
   any vault the user is a member of. The path of least resistance:

   Add `GET /vault/:id` to the existing `VaultController` (Phase 04-03) that
   returns `{vaultId, credentialIds[]}` scoped to any vault where the user is an
   active member (including personal). The existing `GET /vault/personal` stays
   as-is.

2. Bootstrap:
   - Check `keyStore.getBytes("vault_dek:"+id)` — if undefined, show
     "You need to re-accept your invite or re-sign-in to load this vault."
   - `listVaultCredentials(accessToken, vaultId)` → `{vaultId, credentialIds[]}`
   - `apiMe(accessToken)` → email for AAD derivation
3. Decrypt cards using `vaultDek` (from keyStore) instead of `masterDek`
4. Render using `<CardGrid>` + `<CredentialCard>` — same components, pass the right DEK

**CredentialCard** already accepts `accessToken`, `vaultId`, `email`, `reuseMap`,
and `onDecrypted`. It internally calls `decryptCredential` which takes `masterDek`
as a parameter. We need to pass `vaultDek` instead — the CredentialCard and
CredentialEditor components accept a `dek` prop, or we add one.

**Simplest approach**: pass a `dek` prop to `CredentialCard` (rename existing
`masterDek` assumption to a generic `dek` parameter). The CredentialCard already
gets the DEK passed in, it just needs to accept it as a prop. Check the
implementation and make the minimal change.

## T5 — Extend `VaultController` with `GET /vault/:id`

Add `GET /vault/:id` to `apps/api/src/vault/vault.controller.ts`:
- Verifies user is active member of that vault (personal: owner; shared: membership row)
- Returns same `{vaultId: id, credentialIds: [{id, version, updatedAt}]}` shape
- 404 (anti-enumeration) if vault not found or user not a member

## Acceptance

- `/vaults` renders personal + shared vault cards
- `/vaults/new` creates a vault, stores DEK in keyStore, redirects to `/vaults/:id`
- `/vaults/:id` lists credentials encrypted under vault DEK
- `pnpm --filter @simplevault/web typecheck` — clean
- `pnpm --filter @simplevault/api typecheck` — clean
